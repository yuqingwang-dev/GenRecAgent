# GenRecAgent：简历表述与展示提纲

以下为可编辑草稿。只保留你能解释代码和实验的内容，不把外部模型、合成任务或固定流程写成原创算法与自主能力。

## 项目标题和技术栈

**GenRecAgent｜生成式推荐与可验证工具调用 Agent**

Python、PyTorch、BGE、Semantic ID、Transformer、Qwen2.5、LoRA / PEFT、NumPy、pytest。

## 简历精简版

- 基于 Amazon Reviews 2023 构建推荐数据与评测流程，在 112,590 商品、8,151 用户上完成 Popularity、Dense 和 Semantic ID 生成式召回对照；Dense 测试 Recall@20 为 0.03656。
- 实现有效编码约束解码、碰撞候选展开和 item-level 双路融合，接通历史读取、召回、过滤、排序、验证等九个工具动作，支持静态价格约束、历史排除和有界错误恢复。
- 从真实目录执行过的合成任务构造 608 条训练动作，在 RTX 3090 上完成 Qwen2.5-1.5B 的 LoRA SFT；保存数据、模型与代码哈希，并完成同题策略对照及恢复/结束校验消融。

## 实验结果怎么说

推荐质量和 Agent 任务合同分开报告：

- 推荐测试：Popularity Recall@20 为 0.006625，Dense 为 0.036560，生成式 Transformer 为 0.002454。生成式路径仍弱于 Dense。
- 真实 SFT：96 个训练任务、608 条动作，一轮训练；验证动作 NLL 从 0.6410 降到 0.0382。
- 12 个合成任务：Fixed 12/12、Prompt 0/12、原始 SFT 4/12；SFT 仅完成一次可行推荐，另三次通过为正确澄清。
- 取消恢复后 Fixed 为 7/12，取消结束校验后为 10/12；独立 grader 不把空结果的假成功算成通过。

不要只说“模型成功率提高到 33%”而省略任务规模和三次澄清。也不要把低 loss 写成可靠自主规划。RQ-VAE 的质量目标没有达成；下游使用的是明确标注的 RQ-KMeans 基线。

## 追问准备

**你实现了什么，哪些是外部组件？** 数据划分、召回/候选接口、验证环境、动作标签构造和评测是项目实现；BGE、Qwen、PEFT、PCA 和 MiniBatchKMeans 是外部模型或库。

**为什么生成式召回没有更好？** 验证诊断主要指向代码预测不足。约束解码保障合法路径，碰撞展开保留所有候选，但不能补上正确代码预测。

**怎样公平比较？** 同一目录、历史过滤和单目标排名定义；策略使用同一批任务、同一工具与 grader。保留验证/测试边界，没有根据这 12 个测试任务重新调训。

**下一步改什么？** 在新的独立验证任务上增强状态判断和错误恢复，再做更大的表达泛化评测；不是围绕现有测试样本改到全部通过。

**当前有哪些限制？** 合成任务提供规范化意图与约束、语言模板复用；按用户时间划分不等于全局时间切分；目录和价格是静态数据；没有线上 CTR、转化率或生产可靠性证据。
