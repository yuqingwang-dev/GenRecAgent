# GenRecAgent：简历表述与展示提纲

更新日期：2026-10-12。这份求职草稿以事实为主，只保留你能解释的实现与证据，不把外部模型、合成任务或固定流程写成原创算法与普遍自主能力。

## 项目标题和技术栈

**GenRecAgent｜生成式推荐与可验证工具调用 Agent**

Python、PyTorch、BGE、Semantic ID、Transformer、Qwen2.5、LoRA / PEFT、NumPy、pytest。

## 简历精简版

- 基于 Amazon Reviews 2023 构建推荐数据与评测流程，在 112,590 商品、8,151 用户上完成 Popularity、Dense 和 Semantic ID 生成式召回对照；Dense 测试 Recall@20 为 0.03656。
- 实际训练学习型 RQ-VAE 和 47 万参数 Transformer，实现有效编码约束解码、碰撞候选展开与 item-level 双路融合，对码本质量和检索质量分开验收。
- 实现历史读取、召回、过滤、排序、验证等九个工具动作与有界恢复，在 RTX 3090 上完成 Qwen2.5-1.5B 两轮 LoRA SFT，保存完整轨迹和模型/数据/源码指纹。

## 实验结果怎么说

推荐质量和 Agent 任务合同分开报告：

- 学习型 M2：码本用量 256/256/256，93,350 个不同编码，验证重构 MSE 0.00041323，通过预设最低门槛；仍有 26.69% 商品在碰撞组，碰撞比聚类对照更严重。
- 推荐测试：Popularity Recall@20 为 0.006625，Dense 为 0.036560，新 Transformer 为 0.002699、旧模型为 0.002454。新模型仅净增两次 top-20 命中，NDCG@20 反降，不能说整体效果提升。
- 最新真实 SFT：从执行过的合成任务选取 1,080 条动作（1,035 条互异），两轮训练，验证 rollouts 选第 1 轮；完整原始验证 70/72。
- v3 同题合成测试：Fixed 72/72、未专门优化的 Compact Prompt 0/72、原始 Compact SFT 72/72；36 次可行推荐填满、36 次正确澄清，没有运行时 Fixed 接管。输入提供规范化状态和静态资格数量，不证明普遍规划。
- 历史 v2：608 动作、一轮训练、原始 SFT 4/12；取消恢复 Fixed 7/12、取消结束校验 10/12。不同协议分别保留，不拼接为跨版本提升。

不要只写“Agent 成功率 100%”，可以明确写“72 个限定合成测试全部通过，验证仍有 2 次失败”。学习型 RQ-VAE 最低验收已通过，对应 Transformer 已训练评测；默认演示保留旧 K-Means 模型和 Dense 主参考，不混用编码/checkpoint。

## 追问准备

**你实现了什么，哪些是外部组件？** 数据划分、召回/候选接口、验证环境、动作标签构造和评测是项目实现；BGE、Qwen、PEFT、PCA 和 MiniBatchKMeans 是外部模型或库。

**为什么生成式召回没有更好？** 验证诊断主要指向代码预测不足。约束解码保障合法路径，碰撞展开保留所有候选，但不能补上正确代码预测。

**怎样公平比较？** 保持目录、用户目标和 M3 历史窗口，策略用同题/同工具/同预算；验证选模型，再固定设置评测。v3/v2 不合并，旧检索测试已观察，不声称新的独立 holdout。

**下一步改什么？** 在新的独立验证任务上增强状态判断和错误恢复，再做更大的表达泛化评测；不是围绕现有测试样本改到全部通过。

**当前有哪些限制？** 规范化状态和静态资格数量不代表广泛表达泛化，按用户时间划分不等于全局时间切分，目录/价格是静态数据，没有线上 CTR、转化率和生产可靠性证据。
